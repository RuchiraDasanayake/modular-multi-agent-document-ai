# Bounded long-document product extraction

Classification: `idpo/product_auto` is core product extraction; this opt-in path is kept. Default `long_document_profile="reject"` preserves the current 24,000-character behavior. The explicit `"bounded_text_segments_v1"` profile requires an immutable confirmed schema before any run artifact is created. The CLI and queued dispatch must pin this profile; the Python workflow alone does not enable it for existing product requests.

For source text longer than 24,000 characters, the lossless planner admits at most four segments of at most 24,000 characters each. It preserves original page IDs and character offsets with no overlap. Every segment gets one value-model request. The selected strict confirmed-value response format, if enabled, is sent on each request and every response is validated locally. There is no automatic retry or fallback. A failed, refused, truncated, malformed, or unexecuted segment fails the whole document. Partial proposals stay in the document sidecar for diagnosis; the candidate contains no partial extracted values.

Evidence is first checked against segment text, then remapped to the original page using the planned offset and page-text SHA-256. The original page substring must equal the claimed quote. Identical typed scalar values may collapse to one candidate; differing non-null values become `null` with `needs_review`, with all alternatives and evidence in `scalar_conflicts`. Repeated columns use a shared row offset per group for each segment. A cell absent from one column is not invented from another. More than 128 merged rows per group fails the document.

`result.json` records `long_document_plan` (source page hashes, slice offsets, plan SHA-256, boundary policy, planned characters), `long_document_coverage` (planned/attempted/completed segments and characters), model calls, and any partial proposals. Each `manifest.jsonl` entry has a `long_document` summary; `run.json` has aggregate coverage and a hash of the per-document plan receipts. `full_source_covered` means all planned source text was processed by valid segment replies and merged. It does **not** mean every field was found or accurate; source matching and human review remain separate gates.

No overlap means a label and value separated by a segment boundary may be missed. A table row can likewise span segments; row ordinals are deliberately kept separate across that boundary. Sources over four segments, unbreakable spans, invalid page text, or incomplete OCR fail or remain unsupported explicitly. This profile does not solve image-only OCR quality or guarantee extraction across arbitrary file types.
