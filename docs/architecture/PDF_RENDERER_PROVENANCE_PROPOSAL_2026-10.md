# Proposed per-page PDF renderer provenance (12 October 2026)

**Status:** design only. No product code was changed while the v7 2,000-document gate at `111f235` was running.

The current `idpo/agents/preprocess.py::_render_pdf_page` catches PDFium exceptions and silently tries Poppler. `rasterize_pdf_page` records `pdf_source_path` and requested `pdf_rendered_dpi`, but not the renderer that produced the PNG. `idpo/product_auto/workflow.py::_process_document` writes OCR metadata to each `result.json` sidecar but does not include rasterizer metadata. Therefore a successful scan PNG in the v7 gate is not evidence that PDFium rendered it; installed dependencies or artifact filenames cannot answer this retrospectively.

## Minimal proposed change

1. In `idpo/agents/preprocess.py`, make `_render_pdf_page` return a small result object with `image`, `renderer` (`pdfium`, `poppler`, or `none`), `fallback_reason` (bounded enum or `None`), and stored page rotation when the PDF renderer exposes it. Keep the same PDFium `render(scale=dpi / 72)` call, RGB conversion, mutex, Poppler call, and returned image bytes. Catch exceptions as now for fallback, but map their *type/stage* to constants such as `pdfium_unavailable`, `pdfium_open_failed`, `pdfium_render_failed`, and `poppler_failed`; never serialize `str(exc)`, PDF text, or a private path. An invalid page index should have its own code. Preserve the existing `None` result when neither renderer produces an image.
2. In `rasterize_pdf_page`, copy the renderer fields into `Page.metadata` alongside the existing source path and requested DPI. Add `pdf_page_index` (zero based), `pdf_page_rotation_deg` (stored `/Rotate` value, nullable if unknown), and `pdf_render_size_px` from the returned image. Keep `pdf_rendered_dpi` as the *requested* DPI rather than implying measured resolution. On failure, keep the original page image path and set `pdf_renderer="none"` plus a bounded reason, so a missing PNG has inspectable provenance.
3. The direct-PDF fallback in `OcrAgent._ocr_pdf_page` (reached if `rasterize_pdf_page` returns the original PDF) also invokes `pdf2image`. Mark that path as `poppler_direct` in its OCR metadata when it actually returns an image. Without this, a successful OCR result after both earlier renderers failed could still have `pdf_renderer="none"`. If stored rotation cannot be read safely there, use `null`; do not infer it from Tesseract's later orientation correction, which is a distinct operation.
4. `OcrAgent.run` already copies `page.metadata` into the cleaned `Page`; verify those new keys survive that copy. In `idpo/product_auto/workflow.py::_process_document`, explicitly whitelist `pdf_renderer`, `pdf_renderer_fallback_reason`, `pdf_page_index`, `pdf_page_rotation_deg`, `pdf_rendered_dpi`, and `pdf_render_size_px` into each `ocr_pages[]` item. The sidecar already has `source_sha256` at document scope, so no path or page text is needed in the new fields. Use `null` for native-text pages that were never rasterized.

Use source PDF `/Rotate` as a distinct stored rotation field. PDFium exposes it as `page.get_rotation()`; the Poppler path can use the already opened `pypdf` page in `idpo/agents/intake.py` or a bounded metadata read, with `null` if unavailable. This field must not be confused with `ocr_rotation_applied`, the later Tesseract orientation correction. Keep the page index explicit because `Page.number` is one based and `pdf_page_index` is zero based.

## Focused tests and gate

- PDFium success: a two-page synthetic image PDF returns the requested page, renderer `pdfium`, zero fallback reason, correct 0-based index, requested DPI, and pixel dimensions; a rotated synthetic PDF records its stored rotation. Compare PNG bytes before/after instrumenting to ensure this metadata change does not alter pixels.
- Forced PDFium failure: monkeypatch the PDFium open/render call and verify Poppler receives the same one-based page range and DPI, the returned image is unchanged, and `fallback_reason` is a stable code with no exception message or source path. Force both renderers to fail and verify `renderer=none` and an explicit failure code.
- Direct-PDF OCR fallback: force rasterization failure and verify `poppler_direct` only when the OCR path actually opens a page; preserve the OCR failure status when it cannot.
- Product sidecar: process a tiny synthetic PDF and assert `result.json` contains only the whitelisted renderer fields in `ocr_pages[]`; native text has nullable renderer fields. Check `source_sha256` remains at document scope and no new page text/path is copied into renderer fields.

Once implemented, rerun the full pinned 2,000-source gate. Report counts by renderer, fallback reason, rotation, and render failure; verify their sum equals all OCR-requested PDF pages. The current v7 gate cannot supply those counts from its existing sidecars.
