# Reuse frontier for product extraction, 12 October 2026

**Decision:** reuse an established parser or extraction component only at a measured boundary. Prioritize schema induction and linked rows, since these dominate the observed quality gap. The completed [Docling Graph/Qwen3-4B](../evaluations/DOCLING_GRAPH_SCHEMA_DEV_RESULT_20261012.md) and [NuExtract3](../evaluations/NUEXTRACT3_LOCAL_DEV_RESULT_20261012.md) development pilots both recovered zero of 26 linked field pairs under the frozen field mapping. NuExtract3's reference-schema value arm recovered 24/43 complete rows, but only after it received the gold field IDs and shapes, and without verifiable value regions. Keep the source-evidence and human-review contract as the acceptance boundary. This is a research and integration decision, not a claim that a new package improves the product.

A separately precommitted [12-source NuExtract3 follow-on](../evaluations/NUEXTRACT3_GROUP_LEAF_DEV12_RESULT_20261012.md) tested a family-independent grouped-leaf rule and values from the model's own induced schema. It matched **2/52** linked field pairs under the tuned rule versus **0/52** under the original ontology on those new sources, and **0/30** strict complete rows. Its value arm stopped at the frozen 2 GiB RAM floor after seven calls; all twelve sources stayed in the denominator. This does not revise the earlier **0/26** result or justify an automatic-schema route.

## What the repository actually does

`process-auto` accepts PDF, common raster images, TXT, its existing JSON input, and review-only native DOCX, XLSX, PPTX, HTML and EML adapters. The latter emit ParsedDocument v2 source units and resolvable cell locators beside the v1 extraction result; they have passed synthetic fixture checks, not the required real-file or 2,000-source quality gate. It caps an input at 20 MiB, 50 pages and 24,000 characters sent to a model. The product path uses PDF native text/PDFium, Tesseract by default for raster sources, then either a label/value heuristic or two chat calls for schema and values. The only product chat adapter asks for JSON in the prompt; it does not send a constrained output schema. The value verifier checks typed values and exact text quotes, but its candidate representation has text offsets rather than page geometry. Approved recipes do not yet feed extraction. See [`workflow.py`](../../idpo/product_auto/workflow.py), [`logic.py`](../../idpo/product_auto/logic.py), [`provider.py`](../../idpo/product_auto/provider.py) and the [system contract](../SYSTEM_CONTRACT.md).

The execution work is real but does not establish extraction quality. The source-verified [2,000-PDF v8 run](../evaluations/VRDU_2000_NO_MODEL_V8_PROVENANCE.md) covered only registration and ad-buy forms: strict schema F1 **4.2423%**, zero accepted-value F1 and zero proposed linked rows against 7,234 annotated rows. The separate [60-receipt CORD development run](../evaluations/CORD_DEVELOPMENT_NO_MODEL_V1.md) had zero exact proposals for 195 summary values, 458 menu cells and 157 complete menu rows. These are different dataset/scorer contracts; neither measures “any document.” With gold schema supplied, the local 4B [12-PDF pilot](../evaluations/LOCAL_QWEN_ORACLE_SCHEMA_VRDU_TWELVE_PILOT.json) matched 11/98 scalars and 0/111 rows. Better OCR alone cannot close the schema and row gap.

## Concrete component decisions

| Boundary | Decision and reason | Promotion test |
| --- | --- | --- |
| **Automatic schema induction** | **Do not integrate either tested local automatic-schema route.** [Docling Graph v1.9.1](https://github.com/docling-project/docling-graph/releases/tag/v1.9.1) plus Qwen3-4B had low reference-field recall and zero linked-pair hits. The pinned [NuExtract3 six-document pilot](../evaluations/NUEXTRACT3_LOCAL_DEV_RESULT_20261012.md) matched 22/53 reference fields but zero of 26 linked pairs under the frozen alias mapping. It did create nested repeated-object groups; field meaning and relation alignment remain unverified. | Challenge a stronger, fit-verified local or bounded cloud model and a simpler typed schema inducer on the **same** source lock. Preserve failures, source hashes, call/token caps, and held-out documents. Do not auto-approve an induced template. |
| **Graph extraction and source evidence** | **Test, do not replace the verifier.** Docling Graph supports direct and dense extraction through local or remote model backends. Its [provenance ledger](https://github.com/docling-project/docling-graph/blob/v1.9.1/docs/fundamentals/graph-management/provenance.md) deterministically links entities to chunks/pages and sometimes verbatim identifier spans. In direct mode a missing identifier falls back to document scope; dense mode can retain a chunk observation. Neither is a demonstrated exact quote/box for **every** scalar and table cell. | Score each value and linked cell after adapting to our candidate contract. Preserve raw/normalized values and exact source quote or region; send ungrounded and wrong-row results to review. Count all fallback-to-document anchors, hallucinated links, calls and tokens. |
| **Typed extraction from page images** | **Keep pinned [NuExtract3](https://huggingface.co/numind/NuExtract3-GGUF) as an approved-schema candidate only.** The Q4 model and projector ran on this 8 GB GPU. Its separate reference-schema arm matched 13/32 exact positive scalars, 133/192 ordinal linked cells and 24/43 complete rows across six development documents, but one ad-buy source supplied 21 of the 24 matched rows and no field had verified page/box evidence. [Docling `DocumentExtractor`](https://github.com/docling-project/docling/blob/main/docling/.agents/skills/docling/references/extraction.md) offers a beta per-page API using older [NuExtract 2.0 2B](https://huggingface.co/numind/NuExtract-2.0-2B), but also needs a supplied template. | Challenge the conditional route on source-disjoint documents with independently approved schemas, strict evidence verification, review time and complete cost. Do not promote the six-source oracle result to automatic extraction or infer quality from a model-card benchmark. |
| **Cheap conditional text extraction** | **Add [GLiNER2.5 Small](https://huggingface.co/fastino/gliner2.5-small-v1) as an untested CPU comparator for a supplied schema.** Its Apache-2.0 model card describes a 74M-parameter English checkpoint, character-span entity output, and natural-record decoding that retains instance identity. The [library](https://github.com/fastino-ai/GLiNER2) accepts typed fields and long-text chunking. It is schema-conditioned: these capabilities do not generate a schema for an arbitrary document, prove row correctness on our OCR, or provide a PDF pixel box. | On a frozen, source-disjoint set, compare exact typed scalars and complete linked rows against NuExtract3 with the **same supplied schema**, and separately verify returned text spans against OCR and source pages. Include OCR errors, missing schema fields, CPU/RAM/time, and review cost. Do not use this conditional result as automatic-schema evidence. |
| **Mixed-file intake** | **Use bounded source-native libraries in the review-only adapter; retain `docling-slim` as a comparator.** On the same five [synthetic source-locked files](../evaluations/MIXED_FORMAT_NATIVE_DEV_RESULT_20261012.md), `python-docx`, `openpyxl`, `python-pptx`, `lxml`, and standard email MIME handling recovered **45/45** known table cells and **45/45** resolvable locators, including the EML HTML alternative. [Docling-slim](../evaluations/DOCLING_MIXED_FORMAT_DEV_RESULT_20261012.md) recovered **36/45** and missed that alternative. Neither test provides cell pixel boxes or real-document field/row accuracy. Docling's separate PDF parser result was **3/219** permissive gold rows. | Freeze rights-cleared real files with merged cells, formulas, multiple sheets/slides, malformed MIME, and meaningful fields. Compare both adapters on identical sources and reviewable native locators. Do not call this validated format support until conversion, evidence, cost and 2,000-source product gates pass. |
| **Hard tables/scans** | **Do not promote MinerU 4.0.9 Basic or PaddleOCR-VL 1.6.** MinerU colocated exact gold cells for [6/219 permissive parser rows](../evaluations/MINERU_4_BASIC_ADBUY12_RESULT_20261012.md), versus Docling's 3/219; the full [PaddleOCR-VL 1.6 layout/VLM pipeline](../evaluations/PADDLEOCR_VL16_ADBUY12_RESULT_20261012.md) reached 14/219 and 475/808 exact cells, but zero strict exact rows and no cell-level boxes. These parser scores permit extra cells and do not map business field IDs. MinerU's [custom license](https://github.com/opendatalab/MinerU/blob/master/LICENSE.md) adds commercial thresholds. The full PP-StructureV3 CPU profile fails this host's free-RAM guard. | A future cell-box parser must improve mapped rows and verified cell evidence on the same source lock with acceptable latency, memory and rights. Better parser text alone does not clear the extraction gate. |
| **Broad OCR or KIE bundles** | Keep the paired Tesseract/RapidOCR result as an OCR diagnostic. [PP-ChatOCRv4](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PP-ChatOCRv4.md) is an established multimodule KIE pipeline, but its documented call requests specified **keys** and may use a remote LLM/MLLM; it is not an automatic schema or free end-to-end answer. [Unstructured `auto`](https://github.com/Unstructured-IO/unstructured/blob/main/unstructured/partition/strategies.py) may silently select native text, OCR-only or high-resolution paths and fall back when optional dependencies are absent. Defer both until the smaller candidates fail a stated slice. | Require actual engine/module provenance, exact weight rights, source-locked field/row gains and priced end-to-end cost. |
| **State, routing and agents** | Reuse the existing PostgreSQL and Redis services for transactional product state and a bounded queue when product job migration is ready; another database, vector index or autonomous agent loop has no demonstrated extraction benefit. Implement routing as a small, observable rule over native text presence, scan quality, table need and prior failures. Keep reusable “skills” as versioned, reviewed extraction recipes, not executable prompts from a document. See [architecture contract](ADR-0001-evidence-preserving-extraction.md) and [component audit](COMPONENT_REUSE_AUDIT_2026-10.md). | Measure the same documents and total review-adjusted cost with and without each route. Preserve tenant scope, idempotent retries and a holdout for recipe changes. |

## Affordable pilot sequence and stopping rules

1. **Keep the completed CORD OCR and Docling Graph results as diagnostics.** RapidOCR found more receipt text but produced zero exact mapped product fields/rows with the unchanged extractor. Graph/Qwen3-4B missed most reference fields and all linked pairs. Neither should silently become a product default.
2. **Completed:** guarded MinerU 4.0.9 Basic parser-only challenge. Its 6/219 exact rows and 211/808 exact cells do not justify product integration or a 2,000-source candidate rerun. Keep the [reproducible result](../evaluations/MINERU_4_BASIC_ADBUY12_RESULT_20261012.md) as a control for stronger layout parsers.
3. **Completed:** the [NuExtract3 local protocol and result](../evaluations/NUEXTRACT3_LOCAL_DEV_RESULT_20261012.md) separated no-template schema discovery from reference-schema value extraction with pinned weight hashes. Blind schema discovery failed the linked-field gate, while conditional values showed a narrow, high-variance signal. The first [ICORE real-document trial](../evaluations/ICORE_REAL_DEVELOPMENT_SIX_RESULT_20261012.md) stopped on its first connection error with no usage receipt, so it gives no model-quality ranking. Preserve failed attempts and keep provider pricing and a hard spend policy as gates before any large cloud run.
4. **Only if a candidate improves field meaning and grouping, challenge value extraction** with the parser's layout/row evidence, Docling Graph direct/dense, or Docling `DocumentExtractor` on the same scored sources. Compare correct scalar values, cell labels and row links; exact source evidence; reviewer corrections/minutes; p50/p95 latency; CPU/GPU and API usage. Use [DocILE's KILE/LIR evaluator](https://github.com/rossumai/docile) as an external-format cross-check for localized fields and line-item grouping. Our score remains necessary for newly induced field meaning, abstention, critical errors and cost. The official [VRDU evaluator](https://github.com/google-research-datasets/vrdu#evaluation-tools) provides a second known-schema comparison; neither benchmark scorer alone measures useful automatic schema induction.
5. **Then test new file formats on a frozen mixed-format set.** MinerU 4 and Docling are both candidate format adapters; source evidence, rights, failures and resource use decide per format. For any implemented extractor/parser/format change, run a fresh ≥2,000 **distinct-source** execution gate and a disjoint diverse holdout. Report schema F1, exact values, linked rows, source correctness, auto-release precision, failures, review time and cost per correctly released document by family. A 2,000-run gate on the two VRDU families cannot substitute for the diverse holdout.

This order spends local CPU and already cached assets first, uses expensive VLM/API calls only on a bounded failing slice, and turns a package into a product dependency only after it beats the current route on the metric the user actually cares about: correct, reviewable structured extraction per total cost.
