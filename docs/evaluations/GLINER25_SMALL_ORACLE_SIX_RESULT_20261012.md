# GLiNER2.5 Small supplied-schema six-source diagnostic

**Decision: do not promote this candidate to the product.** The frozen, local CPU, text-only diagnostic completed all six development documents after disabling TorchScript JIT in a separately declared runtime arm. It found **4/32 exact positive scalar fields, 0/192 exact linked cells at annotation ordinal, and 0/43 complete rows even with order-independent matching**. This is a result for the supplied-schema arm only. Automatic schema discovery, source-page boxes, arbitrary document types, and production acceptance were not tested.

## Fair comparison and limits

The [NuExtract3 oracle-schema result](NUEXTRACT3_LOCAL_DEV_RESULT_20261012.md) used these same six scored sources and the same value scorer. With reference field IDs/shapes, it scored 13/32 exact positive scalars, 133/192 ordinal-exact linked cells, and 24/43 order-independent strict rows. The GLiNER arm scored 4/32, 0/192, and 0/43 respectively. This supports rejecting **this GLiNER2.5 Small OCR-text configuration** as the next linked-row extractor. It is not a controlled model-only comparison: NuExtract3 also saw downsampled page images, used a different model and prompting path, and its output/template behavior differed. Neither result demonstrates automatic schema generation, visual evidence, generalization beyond six development sources, or lower end-to-end cost.

Memory claims require correction. The parent run recorded sampled `peak_worker_rss_bytes_sampled` values of only 4,014,080–4,026,368 bytes, whereas each worker wrote its own RSS after inference of **861,745,152–1,349,242,880 bytes**. The sampling clearly missed the inference worker's resident memory; the intended 4 GiB per-worker guard is therefore **unverified**, and these values are not peak RSS. The lowest sampled host-wide available RAM was 7,644,422,144 bytes. The memory discrepancy should be fixed before using this runner for resource or scale claims.

No product extraction implementation changed in this diagnostic. The user's separate requirement for at least 2,000 distinct raw-source extractions after a substantive product change remains outstanding for any future integration; this six-source run does not satisfy it.
