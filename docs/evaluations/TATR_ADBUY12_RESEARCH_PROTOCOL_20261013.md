# Table Transformer on the frozen VRDU ad-buy 12: research protocol and implementation gaps

**Status: the first selected PDF was attempted twice under separate gates; both failed before table output, and gold remains unopened.** The pinned safetensors and configs/notices have an [asset-only receipt](TATR_ADBUY12_ASSET_AND_SOURCE_FREE_PREP_20261013.md), and both models passed a [synthetic CPU compatibility check](TATR_ADBUY12_CPU_RUNTIME_COMPAT_20261013.md). The [first-PDF runner](TATR_FIRST_PDF_GUARDED_RUNNER_20261013.md) integrates native words, an isolated pinned OCR subprocess, the Microsoft cell adapter and source-pixel overlays. A corrected first-source trial and manual overlay verdict remain gates before the other eleven or any accuracy claim. No product extraction path changed under this protocol.

**Pre-score threshold amendment (13 October 2026):** [The source-free cell compatibility receipt](TATR_CELL_COMPAT_SOURCE_FREE_20261013.md) found that pinned Microsoft row/column refinement accepts a threshold argument but does not apply it. This arm will apply `score >= 0.5` to every active structure class *before* calling the pinned Microsoft cell functions, as the originally declared per-class threshold requires. Preserve every raw detection and score. Name the measured arm “pinned Microsoft cell functions with frozen 0.5 prefilter”; do not describe it as byte-identical upstream inference. This decision was made before any selected PDF or gold was opened.

The [shared source-free crop transform](TABLE_CROP_SOURCE_FREE_GEOMETRY_20261013.md) now passes rotated and cropped synthetic PDF tests. It does not validate a model-detected crop or first-PDF source overlay.

**Pre-score text-route amendment (13 October 2026):** For each page, use PDFium native word tokens when any valid native words exist; otherwise run one full-page pass in the separate, pinned [RapidOCR 3.10.0 headless-only CPU runtime](TATR_OCR_WORD_SOURCE_FREE_20261013.md) with `return_word_box=True` and `Global.text_score=0.0`. Before word-box construction, require one classifier result per detected line, label `0`, and score above the pinned `0.9` classifier threshold. A 180° or uncertain line is an explicit document failure: the pinned upstream code can recognize its text while attaching words to the opposite source pixels. Preserve accepted line tuples and word quadrilaterals, source order and model/runtime IDs. Feed word boxes to TATR and line tuples to the separate RapidTable table runtime. Do not filter or rank by RapidOCR's reported word score: the pinned source does not establish a correctly aggregated per-word confidence. An OCR failure, absent word result, partial crop word or mixed native/OCR feed is also an explicit document failure, not a fabricated text token. This route was chosen before any selected PDF or gold was opened. Its real-page evidence, latency and accuracy remain unmeasured.

**Pre-score structure ambiguity amendment (13 October 2026):** For every detector-retained table crop, require exactly one structure `table` query with score at least `0.5` after the frozen class prefilter. Zero or multiple retained structure table queries fail the entire PDF explicitly. There is no score-based winner, tie break, retry or crop substitution. This conservative rule was frozen before any selected PDF or gold was opened; its failure rate is unknown.

**Pre-score OCR transport amendment (13 October 2026):** Send a full-page lossless RGB PNG, capped at 35 million pixels and 64 MiB, to one separate pinned OCR process per image-only page. The child has 120 seconds and counts toward the supervisor's 8 GiB process-tree RSS limit. Bound the returned JSON to 16 MiB, 10,000 lines and 50,000 words. Verify its input hash, model/runtime inventory, source order, line/word geometry and upright orientation in the TATR worker. An over-limit transport, timeout or failed child fails the PDF without a partial result or retry. These bounds were set before any selected PDF or gold was opened.

**Post-failure, pre-score v2 text-route amendment (13 October 2026):** The immutable v1 first-PDF attempt failed on a PDFium native-character box outside the rendered page; see the [failure receipt summary](TATR_FIRST_PDF_GUARDED_RUNNER_20261013.md#immutable-first-pdf-attempt-v1). Source-only diagnosis found a partly visible character and three fully outside characters at the right edge. The same token's apparently in-bounds prefix boxes cover blank raster pixels. For v2, if `native_word_tokens` raises `GeometryError`, discard that entire page's native token attempt and invoke the existing pinned full-page OCR handoff once. Record `native_route_rejected: unprojectable_native_character`. Do not catch later table/cell geometry errors, mix native and OCR words, crop only the offending token, filter by raster ink, alter model thresholds, or consult gold. An unavailable, empty, or failed OCR route fails the PDF. The v1 output remains unchanged; v2 requires the new committed gate and fresh `I:\DocAI-Benchmarks\tatr-adbuy12-v2` directory. This amendment responds only to source geometry, before any parser score or first-source overlay was available.

**Post-v2-failure, pre-score v3 text-route amendment (13 October 2026):** The immutable v2 first-PDF attempt stopped in the pinned OCR orientation guard before producing any word boxes or TATR table result. Do not relax that guard. A source-only PDFium audit found one eight-character word on page one with one glyph partly beyond and three glyphs wholly beyond the right edge; its apparently in-bounds prefix has no visible ink. Segment the complete PDFium character stream into words before projecting glyphs, then omit the **entire** word only when a typed out-of-rendered-viewport error occurs. Keep all remaining native words and record the omitted text, PDFium character span, raw and projected glyph boxes, and page degradation flag. Malformed Unicode, nonfinite/zero-area boxes, other geometry failures, more than **one omitted word per page**, over **0.5% omitted nonspace characters**, or zero intact native words fail the PDF. Image-only pages still use the pinned full-page OCR route; never mix page routes. If an omitted glyph's visible footprint intersects a detected table, fail before cell inference. Render a separate 300-DPI omission overlay and require manual review of that region as well as the first nonempty table overlay. Preserve v1/v2 outputs; v3 uses a separately committed one-document gate and fresh `I:\DocAI-Benchmarks\tatr-adbuy12-v3` directory. This amendment uses source geometry and the v2 runtime failure only; no parser score or gold was consulted. Geometric validity of the other native words does not prove that they are all visibly painted or correctly segmented, so this is a research trial only.

## Frozen implementation profile

1. Render each PDF page with PDFium at **300 DPI** and record pixel width, height, source PDF page size, crop and rotation. Use the pinned detection checkpoint for full-page table proposals, and the pinned structure checkpoint on crops with **five image pixels maximum padding**. Preserve the [upstream 800/1000-pixel detector/structure maximum resize](https://github.com/microsoft/table-transformer/blob/16d124f616109746b7785f03085100f1f6247575/src/inference.py), then apply this arm's frozen `score >= 0.5` prefilter to each active structure class before cell postprocessing. Retain all raw class scores and boxes; do not select crops with gold labels. The [structure model labels](https://huggingface.co/microsoft/table-transformer-structure-recognition-v1.1-all/blob/7587a7ef111d9dcbf8ac695f1376ab7014340a0c/config.json) are table, row, column, column header, projected row header and spanning cell.
2. Supply page text tokens with `text` and image-space `bbox`, sorted in reading order, as [Microsoft requires](https://github.com/microsoft/table-transformer/blob/16d124f616109746b7785f03085100f1f6247575/docs/INFERENCE.md). Use PDFium native word tokens if any valid native words exist on the page; otherwise use exactly one full-page RapidOCR word-box pass in the separate pinned CPU runtime with the orientation guard above. Record token source, text, raw line and word polygons, and geometry. This route and granularity were frozen before any selected PDF or TATR score was seen.
3. Safely load the Hugging Face safetensors and produce DETR label/score/box objects. Use a pinned, reviewed adaptation of Microsoft's [`objects_to_structures` and `structure_to_cells`](https://github.com/microsoft/table-transformer/blob/16d124f616109746b7785f03085100f1f6247575/src/inference.py) to align rows/columns, resolve spans, assign each text token at most once, and retain each cell's text, row/column indexes, source tokens and image box. Assign a spanning cell to its starting row for the existing scorer, and retain its full row/column span separately. Hugging Face's object-detection pipeline alone does **not** return filled table cells. Preserve the distinction between missing text and an empty cell.
4. Reproject every table and cell box through the crop, page raster, PDF crop/rotation and page-point transforms to the original PDF page. Reject nonfinite, zero-area, out-of-page, overlapping-grid or ambiguously mapped cells. Emit `ParsedDocument v2` table cells with source-page coordinates only after this check. A quote anchor is allowed only when its exact text can be resolved against retained page text. Box containment is geometry validity, not alignment accuracy.
5. After the first PDF, require successful conversion, at least one table, at least one nonempty cell text with a valid source-page box, and an independently rendered overlay showing the text inside its claimed cell. Otherwise stop, mark the other 11 unattempted, and score the full denominator. After a complete run, independently inspect the first 20 one-to-one exact matched gold rows in frozen order, including every extra or duplicate parser cell. Preserve per-cell visual verdicts. No parser output becomes a released business field without a separate evidence and review gate.

The original v1 runner used CPU/four threads and processed one PDF per subprocess into its then-fresh `I:\DocAI-Benchmarks\tatr-adbuy12-v1` directory outside Git. The amended v2 first-PDF trial uses a new `I:\DocAI-Benchmarks\tatr-adbuy12-v2` directory. Preflight floors: 6 GiB available RAM, 4 GiB free C:, 4 GiB free I:. Stop a worker at 8 GiB process-tree RSS, below 3 GiB available host RAM, or below either disk floor. Limit input to 20 pages and 2 MB per PDF. Cap startup at 180 seconds, conversion at 360 seconds per PDF, first worker wall time at 600 seconds, later worker wall time at 480 seconds, and the full run at 3,600 seconds. Save source and artifact hashes, package/notice manifest, every worker log, raw detections, tokens, adapted cells, score and failure receipt. Do not silently retry, change thresholds, or reuse a partial output directory. A GPU run is a separately frozen hardware and cost arm.

The predeclared research continuation bar is **at least 30/219** complete exact-cell rows, at least one strict exact-multiset row, and every audited cell aligned to source pixels. This only warrants a broader, source-disjoint evaluation. Product adoption additionally needs field attribution, evidence/HITL correctness, throughput, operating cost, failure recovery and the user's separate 2,000-distinct-source gate.
