# Public datasets for extraction evaluation beyond the VRDU development gate

**Research only, 13 October 2026.** This is a source and rights proposal. No data was downloaded, no models were run, and no new quality score is implied. The existing 2,000-source VRDU registration/ad-buy gate is a two-family development cohort; it cannot establish performance on arbitrary documents. The three publisher-declared datasets below add receipts, invoices and forms, but their released evaluation assets are **page images**. They do not establish native DOCX/XLSX/PPTX/EML/HTML extraction quality.

CORD v2 is already prepared as a [source-pinned 60-development/40-reserved split](CORD_SECONDARY_SLICE.md) of its published test 100. The 40 have not been processed by that workflow. Use the 40 **once**, after fixing the candidate, mapping and scoring protocol. Report it as an internally reserved subset of the official test partition, not an official CORD test score. The published CORD labels intentionally omit some merchant/payment fields for legal reasons; do not score invented labels. The current [development result](CORD_DEVELOPMENT_NO_MODEL_V1.md) is a no-model baseline and does not estimate the new candidate's quality.

InvoiceOCR-Synth's author [describes generation, PDF-to-PNG rendering and an arithmetic audit that excluded 62 of 1,000 generated records](https://github.com/alamgirqazi/synthetic-invoice-gen#consistency-audit). The published dataset is [Parquet carrying images and labels](https://huggingface.co/datasets/alamgirqazi/invoice-ocr-synthetic), not a released native PDF corpus. Its six render templates cover invoice, point-of-sale, event-ticket and utility-bill appearances; document-type labels do not imply 15 independent layouts. Use it for controlled robustness and row arithmetic, never as evidence of real-world extraction accuracy.

XFUND tests seven non-English languages and key/value *links* rather than a fixed receipt schema. Predeclare a lossless mapping from its annotated entities/relations to predicted pairs. Keep it as a distinct, noncommercial academic result. If a pipeline lacks a language or cannot emit relations, count those forms as unsupported or failed in its predefined denominator; do not silently select only the languages it handles.

## Frozen evaluation design before any inference

1. Pin each publisher revision, asset SHA-256, original split, license URL and source ID in a rights manifest outside Git. Include attribution in any released aggregate result. Keep original images, document text and gold outside Git.
2. Exclude any raw or visually near-duplicate source already used for training, prompts, threshold tuning or development. Preserve CORD's existing 40 reserved sources. For InvoiceOCR-Synth, partition by the underlying `file_name`/source record, putting all three quality variants in the same partition; the publisher provides only one train split, so create and publish the source-only split rule *before* examining candidate scores. For XFUND, keep the publisher's 350 test forms separate from its 1,043 training forms and freeze any subset by image hash.
3. Freeze dataset-specific ontology mapping, currency/date normalization, null and duplicate policy, row matching, key/value relation matching and evidence scoring before opening reserved gold. No post-hoc schema changes based on the holdout.
4. Run the unchanged product path and a pinned baseline on the same inputs. Report each dataset separately: source count and failures/unsupported, strict schema validity, exact and normalized field precision/recall, linked-row or pair F1, evidence support, review-needed rate, latency, local CPU/memory and measured provider usage. Include all attempted sources in the denominator. Do not combine synthetic and real-world scores into one headline number.
5. Treat public-test results as **source-disjoint within this project**, not proof of model-training disjointness; foundation models may have seen public benchmarks. Add a later, rights-reviewed and human-adjudicated private cohort to test that risk and to cover native office/email formats.

## Explicit exclusions for this immediate extraction gate

- [DocLayNet](https://github.com/DS4SD/DocLayNet) is useful for page-layout detection across document types, but its labels do not supply business field/linked-row gold. Its score would answer a different question.
- [DocILE](https://github.com/rossumai/docile) has relevant invoice/order key fields and line items, but the repository's MIT code license does not establish a matching dataset license; [its data signup was reported as research-only](https://github.com/rossumai/docile/issues/51). Resolve the data terms before treating it as available for product evaluation.
- [PubTables-1M](https://github.com/microsoft/table-transformer) has table structure gold, but its underlying PubMed Central articles can have differing source licenses. It needs a per-document rights filter and does not directly score business field assignment.

**Decision:** Use CORD's reserved 40 first, InvoiceOCR-Synth as an opt-in controlled robustness suite after a hash-pinned split, and XFUND only for noncommercial multilingual research. None replaces a separately adjudicated, mixed-format real-document holdout.
