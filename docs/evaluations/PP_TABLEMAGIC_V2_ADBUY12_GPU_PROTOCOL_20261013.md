## Geometry and rights decision

PaddleX's [v3.7.2 pipeline](https://raw.githubusercontent.com/PaddlePaddle/PaddleX/v3.7.2/paddlex/inference/pipelines/table_recognition/pipeline_v2.py) crops tables, converts detected cell coordinates back into the processed page image, and maps boxes back after table rotation. Its [postprocessor](https://raw.githubusercontent.com/PaddlePaddle/PaddleX/v3.7.2/paddlex/inference/pipelines/table_recognition/table_recognition_post_processing_v2.py) sorts detected boxes and combines them with OCR and separately predicted HTML structure. The [JSON serializer](https://raw.githubusercontent.com/PaddlePaddle/PaddleX/v3.7.2/paddlex/inference/pipelines/table_recognition/result.py) saves `cell_box_list`, `pred_html` and `table_ocr_pred`, but no explicit HTML-cell-to-box ID or PDF user-space coordinate transform; `table_region_id` is also omitted from JSON. **Therefore `cell_box_list` is candidate raster-pixel geometry, not independently trustworthy original-PDF value evidence.** Preserve the runtime region ID separately. For the first 20 one-to-one matched gold rows, or all if fewer, overlay every claimed physical HTML cell and OCR token on the hash-bound page raster, including extra/duplicate/spanned cells. A human must independently read each claimed value in its unique expected row/column box; ambiguity fails. Any future PDF-point coordinates require a separately verified raster-to-PDF transform (page size, crop, rotation and scale). VRDU gold has no cell boxes, so this sample checks source pixels, not benchmark box recall.
