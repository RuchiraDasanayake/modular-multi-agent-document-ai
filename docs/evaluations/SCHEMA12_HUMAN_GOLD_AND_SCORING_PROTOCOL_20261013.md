## Annotation scope and independent gold

Gold is an **extractable semantic graph**, not a list of arbitrary keywords: document fields have a meaning, primitive type, cardinality, optional repeated-object parent, and a source anchor. Two annotators work independently from the frozen original files in a source viewer, with no model name, prompt, candidate schema, OCR/model reply, prior pilot prediction, or scorer output visible. They record start/stop active annotation time. A third person adjudicates disagreements against the original source and the rules below. If independent annotation or adjudication is unavailable, any single-annotator file is a draft and cannot support a primary accuracy result. Record initial agreement and adjudication edits at field, type, group, row and anchor level; do not report only final agreement.

**What to include.** On every PDF page, include explicit form prompts/controls, printed document identity and authored tables; each checkbox/radio choice is a value option of one semantic field unless it represents a separate concept. On HTML, exclude site chrome and annotate the complete authored `main`/article: title/issuer/date/addressee/subject, explicit labelled facts, authored tables, and explicit decisions, recommendations, actions, deadlines or quantified findings stated in prose. On XLSX, inventory every nonempty *visible* sheet and authored table: sheet/table identity, column semantics, row-group structure and meaningful header facts. Record hidden sheets, formulas without cached values, footnotes and external links separately as coverage/interpretation issues; do not silently treat computed results as observed source values. A repeated concept is one field with cardinality/group, not one new schema field per row. A blank form field belongs in schema gold with a null value. Literal numeric zero is present, not missing. Boilerplate instructions, references, citation numbers, navigation and decorative text are not separate business fields unless they themselves carry a requested fact. A substantive candidate field outside this rubric is logged for blinded adjudication, not automatically called hallucinated.

Annotators must make a **full-document pass** for schema and table/row inventory. The 144,389-character fraud assessment and any long workbook remain whole-document scope; a model's 24,000-character cap is a model coverage failure, not a reason to remove their gold. Record per-source pages/sheets/sections and each exclusion with a reason. If a full pass is infeasible, mark that source `gold_incomplete` and withhold full-document schema precision/F1 and perfect-document claims for that source; its failed or unsupported model outcome still appears in operational coverage. Do not retrospectively narrow the source region to a model's successful excerpt.

Each adjudicated field receives a stable, source-independent canonical ID where meanings truly coincide; otherwise use a qualified ID, e.g. `decision_date` versus `publication_date`. Record display label, definition, type (`string`, `number`, `date`, `boolean`, or `array[object]` leaf), cardinality, group path, nullable state, and a source label/statement anchor. Qualifiers such as currency, period, person role and amount basis are part of meaning. Group membership requires a real repeated record in the original, not merely neighboring text. For each group record an ordered set of leaf fields, source row count, row identity/anchor and explicit parent-child relation. Record source-declared requiredness and legal/financial/decision impact as separate risk tags with source reasons; these are not a product release threshold until a domain owner approves one. The adjudicator aligns the two independent concept inventories using only the source, then reports field-set agreement and type/group agreement conditional on aligned fields. Annotate every scalar positive and null for gold fields. For linked value scoring, use **all rows when a group has at most 20 source rows**. For larger groups, freeze a source-only sample of 20: first five and last five data rows, then the remaining rows ranked by SHA-256 of the UTF-8 source hash, group locator and row locator joined with literal U+001F separators until 20 distinct rows are selected. Record the total row count and exact sampled locators before any model output. This is a sampled-row diagnostic, not whole-table recall or perfect-document accuracy; predictions outside sampled rows are unscored for cell precision.

For each positive scalar and sampled cell, store the raw surface value, typed interpretation, and original-source anchor. PDF anchors use one-based page plus a tight rectangle in a frozen rendered page coordinate system and verbatim visible quote; store render DPI/page dimensions and source hash. HTML anchors use the saved source hash, authored DOM element path or stable ID, text offset within that element and quote. XLSX anchors use exact sheet title, cell/range address, and raw cell value or formula with cached-value availability. For a repeated row, preserve a row-level locator plus cell locators. Ambiguous or conflicting printed values stay explicitly disputed until adjudicated; no LLM chooses the gold. A source-native parser may help transcribe, but an annotator checks each proposed label, grouping and scored value against the original; unchecked parser output is silver data, not human gold.

Freeze the adjudicated gold, row-sample list, anchors, ontology, parser view and annotation ledger as immutable versioned files **outside Git**, with SHA-256 receipts in a later protocol amendment before any scored inference. Store only scrubbed aggregate counts and hashes in Git. Corrections after predictions are opened create a new gold version and a separately named sensitivity analysis; they never overwrite the original score.

## Frozen matching rules before model calls

The exact scorer implementation and synthetic fixture tests must be committed and hashed **before** inference. The existing `product_eval.scorer` and `linked_rows` are useful historical contracts but match derived IDs and row ordinals; they cannot by themselves score blind multi-format semantic groups or source-native anchors under this protocol. Reusing them without an explicit projection would give misleading numbers.

1. **Schema, primary:** one-to-one exact canonical ID match. Report TP/FP/FN, type agreement, cardinality and exact parent-group agreement separately. Do not let a right name with a wrong repeated-group relation count as a correct linked field. Invalid JSON/shape and duplicate IDs are failures; deduplication must not use gold. Every gold field remains in recall even if no candidate document/schema exists. Schema precision/F1 is reported only for exhaustively annotated source scope; additional unadjudicated candidate fields are logged and counted as `unscored_extra`, not silently turned into FP or TP.
2. **Schema, secondary:** freeze a field-alias ontology from the **gold annotators' source-only definitions and ordinary terminology**, before predictions. Apply NFKC, casefold and separator/whitespace normalization identically to both sides. An alias maps only when semantic definition agrees and the match is unique in both schemas; then score type, cardinality and group role separately. Generic `date`, `amount`, `price`, `name` and similar ambiguous keys do not map to qualified gold fields without a predeclared qualifier. Collisions stay unmatched and are counted. Report exact and alias results side by side; no post-hoc LLM judge or synonym additions revise either. A third, arm-blind human semantic-match audit may diagnose missed aliases but is labelled exploratory and cannot change the frozen score.
3. **Linked schema:** score each gold repeated group as a group; an unordered gold pair of its distinct leaf IDs is linked only if both fields match uniquely to leaves under the *same* proposed `array[object]` parent. Count all gold leaf pairs, groups and fields; report micro pair recall and mean per-group recall so wide tables cannot hide missed families. A cross-group pair, flattened scalar list or two unrelated arrays is not a linked hit. Documents without gold repeated groups have undefined linked recall, not 100%.
4. **Values and rows:** report blind auto-schema end-to-end results separately from any oracle/reference-schema value arm. Only exact-ID aligned fields contribute to primary values; alias-aligned values are a secondary score. A scalar TP requires correct typed value and field meaning. Raw surface exact and a predeclared NFKC/whitespace-normalized comparison are distinct; dates, currency conversion, arithmetic repair and inferred values receive no silent normalization. For sampled linked rows, permit an assignment edge only when a candidate and gold row share at least one exact aligned leaf/value cell. Select a one-to-one assignment maximizing total matched cells, then matched row count, then source-order tie-breaks. A cell TP belongs to one matched row; duplicate candidate cells/rows cannot each claim the same gold. A **strict content-complete row** has every sampled gold non-null cell in one candidate row and no conflicting or extra mapped cell in that row. A **grounded complete row** also needs a source-valid, gold-supporting anchor for every scored cell or a precise row anchor covering them. Report cell TP/FP/FN and both complete-row metrics within the sampled region, raw and normalized separately, plus each source's total row inventory. Missing schema columns fail their rows. Null, empty string and numeric zero remain distinct. No candidate/failed/unsupported/over-limit source yields zero TP and all applicable gold positives as FN. Unsampled candidate rows are counted operationally but excluded from sampled-row precision; no whole-table F1 is claimed.
5. **Evidence and release:** every proposed non-null scalar/cell has an evidence-present flag. A locator is `source_valid` only if it resolves inside the immutable original and its quote/value agrees with that region; a repeated quote without disambiguating page/DOM/cell/box fails. It is `gold_supporting` only if the resolved location supports the matched field and value: PDF quote plus rectangle overlaps the annotated visible value/label region, HTML anchor refers to the same authored element/span, or XLSX sheet/cell/range agrees with the gold. Record invalid/missing/ambiguous locators and correct-value-with-valid-evidence over **all scored positives**, not just accepted values. Geometry presence is not proof of pixel accuracy; two arm-blind reviewers inspect a source-hash-ordered sample of at least 20 candidate PDF boxes per arm (or all if fewer) and every disputed/high-impact box. Report inter-reviewer disagreement. No output in this diagnostic is auto-released solely because it is valid JSON or has a plausible quote.

Report per-source and per-format/family/overlap-cluster counts, then micro and document-macro values; undefined denominators are `null`. Include all 12 planned source IDs in coverage, failure, latency and schema-recall denominators. Do not pool blank forms' zero positive-value denominators with populated tables as if they measured value accuracy. Show proposal and accepted/reviewed states separately, explicit abstention, unsupported/failed/over-limit, zero-as-missing and false-accepted values. A 12-source diagnostic is for mechanism selection, not a population accuracy estimate; publish the source-level paired outcomes rather than a spurious precise confidence interval.

## HITL and cost measurement

After raw model replies, prompts, source-view hashes and outputs are sealed, run a **separate** review study. Reviewers do not see gold or model identity. Use the same original-source viewer, editing controls, instructions and release policy for each arm. Assign independent reviewer/arm pairs per source; balance reviewer and arm order across sources so seeing one candidate does not teach the same reviewer the answer for another arm on that source. Log active editing/inspection seconds, pauses, field/row creation/deletion/correction, evidence inspection, disagreements, abstentions, escalation and final release. Keep gold annotators out of candidate review. An independent adjudicator compares the reviewed output to frozen gold and records residual field/row/evidence errors. Report median and per-source schema-edit minutes, full review minutes, actions, correction rate, automation coverage, reviewed perfection on the *fully labelled scope*, and reviewer-to-reviewer variation. A draft UI or one reviewer cannot support a comparative review-time claim.

For each arm record parser/OCR time, schema and value call time, retries (including failed attempts), CPU/GPU seconds and peak memory, storage/network use, provider-reported tokens, settled API charge, and active reviewer time. Give local hardware/electricity and reviewer labor explicit measured or scenario assumptions; an unpriced component is `unknown`, never zero. Report the component vector and a sensitivity table across stated hourly reviewer rates. **Cost per correct reviewed document** equals all measured processing, retry, setup amortization, storage, API, hardware and review cost divided by released documents correct on the fully labelled agreed scope, with the denominator and omissions shown. If no document qualifies, report undefined/infinite rather than a low cost. With sampled table rows, use `cost per correct sampled-row/field` only; do not call it cost per perfect document. Cloud cost cannot be estimated from token count without a verified rate card and settled usage. Rights and provider spend/data gates are separate prerequisites.

## Run ordering and stop rule

1. Complete overlap/rights audit, independent source-only annotation, adjudication, gold/alias/row-sample freeze, and scorer synthetic tests. Archive the pre-inference hashes and access log. No candidate may shape source selection, labels, ontology, sampling, prompts or scorer.
2. Freeze each candidate's model/weights, prompt, source representation, parser/OCR revision, context/character limits, runtime, budget and retry policy. A model-only A/B needs the *same* source representation and budgets; product-path arms may differ in parsing but must report that difference. Never silently truncate a long document. A future section/page/sheet chunker is a new separately versioned arm with source-coverage and merge receipts.
3. Run one immutable attempt per planned source/arm, seal raw responses and hashes, then open gold for scoring. Missing and stopped outcomes remain visible. If an integrity or independence check fails, stop the primary comparison and publish the failure/auxiliary observation; do not replace a document after seeing model output.
4. Advance a candidate only after it produces correctly linked and source-supported rows/fields, reduces human correction or total cost on a larger permitted holdout, and passes the separate **at least 2,000 distinct original documents through the changed end-to-end product path** gate. This 12-source protocol does not satisfy that gate or revise the accepted ICTAR submission or frozen October research evidence.
