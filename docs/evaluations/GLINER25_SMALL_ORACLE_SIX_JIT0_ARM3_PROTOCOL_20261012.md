The [Transformers maintainers' issue](https://github.com/huggingface/transformers/issues/41472) identifies a Python 3.13.8 `inspect` regression that makes TorchScript fail to parse a comment between the DeBERTa-v2 decorator and function definition; their [follow-up](https://github.com/huggingface/transformers/issues/44855) records the same stack and fix. The local installed source has that exact decorator/comment sequence. This matches the observed traceback; it is a runtime compatibility defect, not a field or row score.

A local, offline preflight with the same interpreter, weight and `PYTORCH_JIT=0` imported `DebertaV2Model` and loaded a CPU `BoundaryExtractor` successfully.
