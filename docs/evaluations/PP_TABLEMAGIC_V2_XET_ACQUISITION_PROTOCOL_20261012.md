## Hard bounds and failure accounting

- One asset child process at a time; Xet fixed download concurrency **2** and maximum simultaneous file downloads **1**. Internal Xet request retries are set to at most **3** with a **1-second** base delay and **90-second** requested retry duration. Xet decides which failures are retriable; the caller adds **no** retry. Because a library retry-duration setting is not a hard process limit, the parent terminates the entire process tree at **900 seconds per asset** or **5,400 seconds total**.
- Hub metadata timeout **20 seconds**, HTTP fallback timeout for small Git files **60 seconds**, Xet connection/read timeouts **20/60 seconds**. Xet download buffers are explicitly capped at **512 MiB**. `HF_HUB_DISABLE_XET=0`, token transmission is disabled, Hub/Rust debug logging and implicit tokens are disabled, and telemetry is disabled. No signed CDN URLs or token values are written to structured receipts or the sanitized report.
- Before starting: host available RAM at least **6 GiB**; continuously: host available RAM at least **3 GiB**, child process-tree RSS at most **3 GiB**, C: free at least **4 GiB**, E: free at least **2 GiB**, and the entire new root at most **3,500,000,000 bytes**. A guarded copy also checks projected bytes before each 4 MiB write. The parent samples the child and host every 2 seconds. These are local storage limits, not a claim that the SDK exposes an exact network-byte counter.
- The new root must not exist before the run. Every reused or downloaded file gets a SHA-bound receipt with route, model/revision, size/digest, resource sample and status. Failed children, logs, cache partials and not-attempted assets remain visible. The arm writes an acquisition summary and seals the entire new-root inventory outside Git. Any package, source, transfer, route, digest, storage, time or runtime failure is **no-go** for TableMagic inference. A failed acquisition yields no parser-quality score; all 12 documents remain unprocessed rather than being silently dropped from a denominator.

The first arm's no-score decision remains intact. Completion of this second acquisition arm only supplies verified local model files for the already frozen TableMagic parser pilot. The pilot still requires its separate 12-PDF run, HTML row score and independent visual overlay audit before any research or product promotion decision.
