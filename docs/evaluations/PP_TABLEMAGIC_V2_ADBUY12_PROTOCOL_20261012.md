## Frozen profile and outputs

Run the official **full** table pipeline on CPU with local `paddle_static`, one PDF process at a time: layout detection `PP-DocLayout-L`, table classifier, wired and wireless `SLANeXt`, wired and wireless `RT-DETR-L` cell detection, OCR detection and recognition, plus table orientation classification. `use_doc_orientation_classify=False` and `use_doc_unwarping=False` disable the *page* preprocessing branch so cell rectangles can be checked in PDF page raster coordinates. The table orientation module still uses `PP-LCNet_x1_0_doc_ori`. This omits only the optional `UVDoc` asset; rotated or warped failures remain counted. End-to-end-only structure modes and detector-to-HTML modes remain false. OCR is enabled; no API calls, VLM route, or gold-dependent configuration is permitted.

The worker reads the hashed installed YAML, injects the nine verified absolute local model directories (including the table orientation node omitted by the high-level wrapper's model-dir arguments), then constructs `TableRecognitionPipelineV2`. It saves each official page JSON unchanged, the exact `output_img` raster as PNG for later visual review, and a companion record of actual raster dimensions and runtime `table_region_id`s. Each raster is SHA-bound to the conversion receipt. Static review of pinned `pipeline_v2.py` shows that the disabled page-preprocessor path still sets `doc_preprocessor_res["output_img"]`, and both table branches assign `table_region_id`. A different runtime shape is a recorded failure, not grounds to change the profile during this challenge. Only source PDF and model paths are passed to the worker; gold opens only after conversion.

## Resource and stop rules

- Before the run: host available RAM at least **6 GiB**, free C: at least **4 GiB**, free E: at least **2 GiB**, exact source/model/runtime hashes, and an empty output directory. The parent coordinates release of competing CPU jobs.
- During each worker: process-tree RSS at most **8 GiB**, available host RAM at least **3 GiB**, C: and E: floors unchanged. Model startup must emit `startup.json` within **180 seconds**. The first three-page PDF must finish within **600 seconds**; later PDFs within **480 seconds** each. Total conversion time is at most **3,600 seconds**. Resource or timeout failure stops further PDFs; all remaining gold rows stay in the score denominator.
- Smoke requires all expected pages, contiguous `page_index`, `model_settings` confirming layout+OCR and no page preprocessor, real `table_res_list[].pred_html` HTML, at least one valid table, cell box, layout table region and table OCR box. Failure is a no-go for the other 11. An ordinary later PDF failure is retained and scored as empty if resources remain safe. Raw partial JSON, worker logs, samples and SHA256 conversion receipts stay outside Git.

## Primary and separate evidence measures

The primary scorer reads **only** `table_res_list[].pred_html` tables with `<table>/<tr>/<td>` or `<th>`, uses the same NFKC/case/whitespace normalization and existing `score_tables` one-to-one matcher as Docling, MinerU and PaddleOCR-VL. It reports exact cell text, surface presence, complete exact-cell gold rows (all gold cells in one distinct parser row, **extra parser cells allowed**) and strict entire-row exact-multiset matches. It never promotes general OCR text or Markdown to a table row. Hash mismatches invalidate the run; malformed but SHA-matched outputs count as parser failures. The locked comparator is PaddleOCR-VL **14/219** complete exact-cell rows and **0/219** strict rows, MinerU 6/219, Docling 3/219 and pdfplumber `text` 4/219. The NuExtract oracle-schema row metric is different and cannot be compared directly.

The secondary audit counts physical HTML cells, model-detected cell rectangles, layout table rectangles and OCR text rectangles separately. It checks finite, positive boxes within the page raster, whether physical-cell and box counts agree, and how many nonempty HTML cells have an exact OCR-text composite inside exactly one box. This is a **heuristic**, especially for duplicate values, spans, split OCR and rotation. The official serialized JSON has no HTML-cell-to-box ID and omits runtime `table_region_id`; the companion retains only that real runtime ID. A text/box match is not accepted field-level source evidence. If the saved output cannot establish cell-to-source correspondence, report it as unavailable. Never invent box positions.

The **predeclared manual overlay sample** is the first 20 one-to-one exact matched gold rows, or all if fewer, sorted by frozen document order and numeric gold row ID. Reconstruct the existing deterministic `score_tables` matching without altering the primary score. For each sampled match, retain its page/table/parser-row locator and review **every nonempty physical HTML cell of that parser row**, including extras and duplicate values. Draw numbered detected cell boxes and OCR boxes over the SHA-bound `output_img` PNG at its recorded dimensions; retain the overlay and a per-cell verdict outside Git. A cell passes only if a human can identify a unique box for that HTML cell and independently read its claimed text in the source pixels at the expected table row and column. Ambiguous box order, spans, rotated text, empty boxes, conflicting duplicates and unreadable pixels fail that cell. Report the sample numerator and denominator, sampled row IDs, failures and unreviewed count. A successful text/box-count heuristic alone cannot pass this audit. With no explicit HTML-cell-to-box contract **and** no independent pixel check, label alignment **unverified**. Passing the sample establishes only sampled alignment, never field-level source evidence for unsampled cells.

A completed 12-PDF pilot merely warrants broader research if it reaches at least **30/219** complete exact-cell rows, at least **1/219** strict row and all sampled cells pass the independent visual overlay audit. Even that remains far below product quality. Product promotion requires diverse disjoint documents, field-attributed extraction and evidence evaluation, HITL review behavior, throughput/cost evaluation, and only then the user's 2,000-document gate.
