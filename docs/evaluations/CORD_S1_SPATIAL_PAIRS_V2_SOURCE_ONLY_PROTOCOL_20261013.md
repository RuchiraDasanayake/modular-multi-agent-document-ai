# CORD S1 spatial pairs v2: frozen source-only protocol

**Scope:** a separate research candidate arm over the same 60 sealed CORD development PNGs and the existing RapidOCR full-page **line** graph. It changes neither the [sealed v1 three-line rule](CORD_S1_SPATIAL_ROWS_SOURCE_ONLY_PROTOCOL_20261013.md) nor product extraction. The [v2 runner](../../product_eval/cord_spatial_pair_rows.py) must verify the source cohort, PNG hashes/dimensions, 120-record graph SHA-256 `4eb59422fddeb51778150f3cb79ed8f4ff9a34572e4f74b5974d680aaecd4b0d`, Rapid graph pointers, and pinned input parser-rule bytes before producing output. No gold, creator quadrilateral, reserved-40 source, model, or receipt-specific field value is an input.

## Source-only motivation, fixed before v2 run

The v1 rule admitted only 14 line triplets on 8/60 sources. Its three spatial slots are a poor fit for two OCR regions per visual row and for receipts whose columns occupy the same global image third. Before implementing v2, we selected a deterministic sample of the 52 v1-abstaining pages: sort by source SHA-256 and inspect indices `0,7,14,21,28,35,42,49`. This uses only the original PNGs and pinned RapidOCR line polygons/text. The sample showed combined quantity/name text in one OCR line with an amount line to its right (`test/0075`), mixed split and combined prefix lines (`test/0006`, `test/0085`), line boxes from adjacent rows overlapping (`test/0085`), and two-region rows without a separate prefix (`test/0044`, `test/0054`, `test/0066`, `test/0068`, `test/0072`). The sole page without any left/right pair under the proposed geometric threshold is `test/0013`; RapidOCR missed its right amount column. These are visual/source observations, not annotated item-row judgments.

A preliminary **upper bound on geometric support** found at least one nonoverlapping left/right line pair with half-shorter-height vertical overlap on 59/60 sources, including 51/52 v1-abstaining sources. It found 570 raw pairs overall, 477 on v1-abstaining sources. Headers, totals, and false OCR can satisfy the same rule. Those numbers do not estimate extraction recall or precision.

## Frozen v2 rule and output contract

1. Every verified RapidOCR line remains an indivisible `ocr_line` with its existing exact `node_id`, original-pixel polygon, raw text span, locator, and parser/config provenance. v2 uses only line geometry and image width. No word box or cell is inferred.
2. For every ordered pair of distinct line boxes, call the first **left** and second **right** only when `left.x_max <= right.x_min` and their vertical box overlap is at least `0.5 * min(left_height,right_height)`. Keep **all** qualifying pairs, capped at 1,024 per page; exceeding the cap fails closed. A page with none abstains as `no_spatial_pair`.
3. For a pair, a third **prefix** line is a geometry-only alternative when its center is at least `0.02 * image_width` left of the left line's center, its width is no greater than the left line's width, and it has the same half-shorter-height vertical overlap with both pair lines. All such prefix IDs are retained in deterministic order by vertical center distance to left, horizontal center distance to left, and raw input index. With exactly one, `prefix_node_id` points to it; with multiple, `prefix_node_id=null` and `prefix_status="ambiguous"`; with none, status is `none`. No line text or inferred quantity is used.
4. Rank pairs by ascending vertical center difference divided by the taller line's height, descending vertical overlap fraction, ascending horizontal gap divided by image width, then input raw indices. `rank` is one-based. A stable `pair_id` digests source hash, locked graph hash, v2 rule hash, and ordered left/right exact node IDs. The record includes both IDs, optional prefix ID and all prefix alternatives, geometry scores, rank, and `ambiguity_status`; it copies no OCR text or semantic label.
5. Record a `shared_line` conflict for any two pairs sharing a left/right node. Otherwise record `crossing_order` when the two pairs' left centers and right centers occur in opposite vertical order. Every conflict stores both exact pair IDs. `ambiguity_status="conflicted"` means at least one pair conflict; prefix ambiguity is separately explicit. Conflicts and alternative hypotheses remain in the file. No best pair is silently accepted or projected to an item row.
6. Emit one page record for each of the 60 sources, including pages without pairs. The output carries source hash/IDs, original image size, pinned input graph/line-rule hashes, v2 rule hash, pair list, conflict ledger, status, and reason. The source-free receipt reports source/pair coverage, conflict and prefix statuses, and output SHA-256.

This v2 artifact is a **candidate catalog**. A model or later scorer may use its exact IDs to cite a source line, but the catalog itself does not assert item/price/quantity meaning, OCR correctness, a table, a cell, or a verified row. OCR omissions such as the right column of `test/0013` need a separate OCR/parser candidate; geometry cannot recover absent text. Any v2 quality score requires a separately frozen mapping and scorer protocol before opening development gold. The user's 2,000-distinct-source end-to-end gate applies to any subsequent product change.
