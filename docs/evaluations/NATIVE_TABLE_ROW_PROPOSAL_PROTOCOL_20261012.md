# Native table-to-linked-row proposal: staged protocol

**Decision, 12 October 2026:** Add a bounded, deterministic, **review-only** proposal arm for the five source-native formats after the current native-intake 2,000-source gate is sealed. It should reuse `ParsedDocument` v2 table cells, not infer rows from flattened page text or add a model call. This is a design, not an implemented accuracy claim. The five synthetic sources currently yield 45/45 exact, source-resolvable cells, while the no-model product run proposes no linked fields or rows ([native diagnostic](MIXED_FORMAT_NATIVE_DEV_RESULT_20261012.md), [fixture manifest](../../product_eval/fixtures/mixed_format_docling_v1/manifest.json)).

## Contract and narrow implementation

1. Run this arm only when `native_parsed` exists and `model is None`. Keep the existing scalar `baseline_proposals`, cap the combined schema at 24 fields, and never overwrite a scalar or another table's field ID. A later paired test can decide whether to merge with model output. Parser text is data, never instructions.
2. Verify the parsed source hash equals the uploaded source hash. For each proposed cell require **one** `SourceAnchor` whose `unit_id` exists, nonempty `text_span` exactly covers the complete nonblank `TableCell.text`, `quote` equals that span, and `native_locator` is nonblank. Convert its unit to the existing one-based `page` index and its code-point span to `{page,start,end,quote}`; verify the page text slice. The page number is a product source-unit ordinal (sheet/slide/MIME part for native files), not a physical printed page. Preserve `table_id`, unit ID, grid row/column, and native locator in an auditable sidecar mapping keyed by proposed field ID and row ordinal. The v1 linked-cell API rejects extra keys, so do **not** silently put locator fields into those cells. The review UI can join an exact evidence span to the v2 cell, as it does now; require a unique cell match before presenting a row as grounded.
3. Consider only a rectangular table with one cell at each grid position, no spans/merges, contiguous columns, one header row followed by **2–128** complete data rows, 2–8 columns, and at most 500 code points per nonblank cell. For DOCX/PPTX's weaker header evidence, require **3–8** columns. Reject a table with a blank/duplicate header, blank data cell, duplicate normalized field ID, extra header/subtotal/footer row, repeated header row, formula, or ambiguity about a row's membership. This first arm intentionally misses sparse and complex tables rather than shifting rows. Zero (`0`) is a populated value.
4. A header candidate must have short, distinct, nonnumeric labels (2–40 characters, at most six words) that normalize to valid IDs. Every body row must differ from the header and retain the same coarse per-column value shape; at least one column must be consistently numeric and at least one consistently textual. For HTML/EML, require the first grid row to be real `<th>` cells in a `<thead>` as checked against the source DOM; for XLSX, require the cells to belong to one **declared** worksheet table with a header row and exact range, and verify the sheet/rows/columns are visible and body cells are not formulas against the hash-checked workbook. For DOCX/PPTX, which do not expose header semantics in the current v2 contract, use the stricter rectangular/shape rule and record `header_basis=content_shape_only`; never treat this as proof of business meaning. Reject HTML `role=presentation`, hidden/ARIA-hidden cells, and obvious navigation/layout tables. CSS or script-rendered visibility is unavailable in this source-only path; retain review and measure false proposals. The current v2 record alone lacks Excel visibility/table-range and HTML header/visibility flags; the smallest source-native read or explicit parser metadata must supply them. If these checks cannot be made, abstain for that format.
5. For each eligible table, create one `array[object]` field per header, using `normalize_field_id(header)` and one group derived deterministically from source unit plus `table_id`. Do not assign a domain meaning such as `line_items` from shape alone. Use the physical parser grid to set a shared **zero-based data-row ordinal** across every column; emit raw cell strings, one exact cell quote/evidence per value, cell `status=accepted` only in the existing *text-grounded* sense, parent field `status=needs_review`, `review_state=pending`, and document `needs_review`. Human approval of **every column and row relation** is required; no auto-release, approved-recipe promotion, or shadow-to-active change follows from this arm. Record why each table was proposed or declined.

The five frozen fixtures have `Item | Qty | Amount` and two complete body rows. A successful implementation should propose **15 linked schema fields, 30 exact linked cells, and 10 complete data rows** across the five sources, each joined to a unique v2 cell and independently reopened original locator. This is a fixture target, not general accuracy. Current review accepts `array[object]` columns with shared ordinals but only text offsets in v1 candidates ([logic](../../idpo/product_auto/logic.py), [workflow](../../idpo/product_auto/workflow.py), [server verifier](../../frontend/src/server/product-auto.ts)); the sidecar is needed to keep source-cell identity without weakening that validator.

## Adversarial and real-file evaluation

Freeze the code, fixture hashes, candidate-selection rules, scorer, and corpus before inspecting outcomes. Add negative fixtures: a two-column key/value layout, navigation HTML table, duplicated/empty headers, rowspan/colspan and DOCX/PPTX merges, blank middle cell, repeated header, subtotal/footer, hidden HTML/Excel content, Excel formula and table-free grid, multiple tables with colliding names, malformed locator, repeated identical cell text, and supplementary-Unicode spans. An anomalous table must yield **no** partial linked proposal in this arm. Test machine proposal review end to end, including source hash recheck at final review, malformed sidecar rejection, and correction of a row without losing an adjacent row.

Then assemble a rights-cleared, source-disjoint real set with at least 20 table-bearing documents **per format**, plus layout/non-table negatives; record provenance and permission for local/cloud processing. Annotate field IDs/types/groups, complete rows, every exact cell and source location, and whether a table should be abstained. Score field/type/group precision and recall, exact linked-cell and complete-row precision/recall, source-cell identity, table false-positive rate, abstention, reviewer correction time, p50/p95 latency/RSS, and cost per correctly reviewed document. A source quote alone is insufficient: a cell must also map to the right header and row. Predeclared promotion floor for this conservative arm: **zero wrong source-cell locators**, at least **95% exact complete-row precision** on proposed real rows with per-format denominators, and **zero automatic releases**. Report recall even if very low; do not tune on the holdout.

After any product implementation, run a **fresh >=2,000 distinct raw-source extraction gate** with receipt/hash verification and include all unsupported/failed documents. The existing two-family VRDU PDFs provide a regression/operational gate but cannot measure these new native-format proposals. A mixed-format 2,000-source gate requires a separate rights-cleared corpus; do not count reruns or synthetic variants as distinct sources. Compare the same sources with/without this arm, preserving review and resource receipts.

## Why the conservative boundary

Official [python-docx table documentation](https://python-docx.readthedocs.io/en/latest/user/tables.html) describes merged/omitted cells and the default grid approximation; [openpyxl's table guide](https://openpyxl.readthedocs.io/en/3.1/worksheet_tables.html) distinguishes declared tables and string headers; [python-pptx's table guide](https://python-pptx.readthedocs.io/en/latest/user/table.html) distinguishes merge origins and spanned cells. These libraries expose structure, not a reliable business schema. The linked-row failures in the [2,000-source baseline](VRDU_2000_NO_MODEL_V8_PROVENANCE.md) and local model pilots make a parser-confirmed, reviewable row proposal worth testing, but neither synthetic 45/45 cell recovery nor exact quotes prove semantic extraction quality.
