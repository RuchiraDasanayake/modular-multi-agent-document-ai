# Evidence-first automatic schema candidate: decision and local evaluation protocol

**Decision, 13 October 2026:** build a research-only, source-indexed schema candidate before changing `process-auto`. The candidate must derive field and repeated-group proposals from parser/OCR labels, table headers, columns, and source locators, then use **one bounded local model call** to name and type those proposals. Bind every proposed value to the source node from which it came. Keep inferred meanings and all new schemas in human review. The first comparison is on existing locally usable labeled sources; it cannot establish general-document accuracy, a production cost saving, or an ICTAR paper result.

This is a design hypothesis, **not a measured model win**. The owning surface is `product_eval` research evidence, action **keep**. The unchanged `idpo.product_auto` route remains the comparator. A product adapter is a separate decision after the gates below.

## Why this candidate

| Evidence from this repository | Consequence |
| --- | --- |
| The mixed 2,000-original-source no-model path executed cleanly but had **3.375% strict combined schema F1**, zero linked-cell/row proposals against **24,738 cells and 6,541 rows**, and 2,000/2,000 documents needing review. The combined F1 mixes non-equivalent gold scopes. | Operational throughput is established; useful automatic structure and review-adjusted cost are not. A proposed row relation needs its own score. |
| Docling Graph v1.9.1 with local Qwen3-4B matched **7/53** narrow reference fields in its per-document arm and **0/26** linked field pairs in six scored development documents. | A complete graph framework did not rescue this schema-induction configuration. Keep it as a comparator, not a new product service. |
| NuExtract3 Q4 blind discovery matched **22/53** fields under frozen aliases but **0/26** linked pairs in the earlier six-source study. Its reference-schema value arm, given gold IDs/shapes, recovered **24/43** complete rows, heavily concentrated in one source. A later 12-source grouped-leaf development study recovered **2/52** linked pairs and **0/30** strict self-template complete rows; that value run was incomplete after a RAM stop. | The gap between conditional extraction and blind end-to-end extraction motivates source-indexed schema and row witnesses. Neither NuExtract3 result justifies automatic release. |
| ICORE Luna 6 matched **0/20 exact reference schema IDs** and **0/22** gold linked rows on two public PDFs, with three calls and 10,538 reported tokens; settled USD cost is unknown. | Cloud transport is not a quality or cost shortcut. No ICORE corpus call belongs in this protocol. |
| TATR detector/structure weights, RapidOCR word handoff and a separate RapidTable table-only runtime passed **synthetic** CPU checks. No selected PDF has a scored row or verified cell-to-page evidence. | Their table outputs may become input witnesses only after the frozen real-PDF parser gate. Do not assume synthetic cells solve automatic schema semantics. |

The current `process-auto` model route sends up to 24,000 extracted characters, asks for at most 24 fields, then asks a second model call for values. JSON is requested in prose rather than enforced by a response schema. `resolve_evidence` verifies a unique quote in its own extracted page text; this is **not** proof that the quote belongs to the right field or that a PDF box overlaps the visible source. Every dynamic schema stays in review. Native DOCX/XLSX/PPTX/HTML/EML adapters preserve source-native cell addresses where available; that does not make every embedded object or image extractable. A document above 50 PDF pages, 20 MiB, or the model character cap has a current coverage limit. The source-indexed candidate must record these limits, never silently truncate or label an unsupported language/format as correct.

**Source-only v1 stop, 13 October:** the frozen [CORD spatial-triplet arm](CORD_S1_SPATIAL_ROWS_SOURCE_ONLY_RESULT_20261013.md) admitted only **14 generic row candidates on 8/60 images**. Even if all 14 were exact and distinct item rows, its one-to-one strict-row result cannot reach the predeclared **40/157** development threshold. No v1 receipt-model calls or gold scoring are warranted. A [separately frozen v2 pair catalog](CORD_S1_SPATIAL_PAIRS_V2_SOURCE_ONLY_RESULT_20261013.md) contains **570 geometry hypotheses on 59/60 images**, of which **287 conflict** with another pair. This removes the trivial v1 upper-bound stop, but the pairs are not typed cells or verified item rows. V2 still needs a bounded, source-indexed projection, semantic selection, prompt/output contract, and independent evidence audit before any source-model call. The [synthetic grammar probe](S1_SYNTHETIC_GRAMMAR_PROBE_PROTOCOL_20261013.md) is a tested harness but has not called a model.

## Concrete candidate S1

1. **Immutable source graph.** The existing bounded parser produces source units, text spans and native cell locators. A PDF/image table witness is admitted only after a separately scored parser yields crop/page coordinates and OCR words with valid orientation. Every node carries original-source SHA-256, parser/asset hashes, page or native unit, and exact source locator. OCR words, table cells and line order are distinct node types. No gold field IDs, values, aliases, or family names enter this graph.
2. **Small schema proposal.** Deterministic code enumerates label/value relationships and table header/column candidates, including uncertain columns. A single pinned local NuExtract3 Q4 call may rename, type and group these *enumerated* candidates; it cannot create an unreferenced field, change source node identity or invent a row ordinal. This is a new profile and prompt, not a reinterpretation of the prior NuExtract3 results. An implicit role, such as receipt item price without a printed header, must cite a column/row witness and be marked `inferred_meaning`. Invalid, duplicate, over-budget, or unsupported output becomes an explicit failure/abstention. Use a frozen JSON grammar with server-compatibility probes and independent parser validation: [llama.cpp supports a JSON-Schema subset](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md), but a grammar enforces shape, not field meaning.
3. **Source-indexed values.** Materialize values by pointers to source spans/cells, preserving typed raw and normalized values separately. Do not generate row links from text-only same-number ordinals or accept a quote that appears at multiple locations. A model-generated value without an exact source pointer stays unaccepted. Human approval, not model confidence, activates a versioned recipe for recurring families. Unseen families continue to receive per-document proposals and review.
4. **Extension route.** Keep one parsed-document/evidence contract. Add a parser or language pack behind a format/script capability check and score that slice before enabling it. Use local CPU native parsing or validated OCR first; local GPU and ICORE are conditional per-tenant routes. No vector database, agent loop, new microservice or autonomous tool use is justified by current extraction evidence.

The existing official [NuExtract3 model card](https://huggingface.co/numind/NuExtract3) describes template generation and structured extraction, but the local failures above take precedence over its general capabilities. [Docling Graph's official template generator](https://github.com/docling-project/docling-graph) can induce schemas from example documents but the measured v1.9.1 setup failed this cohort. [GLiNER2.5](https://huggingface.co/fastino/gliner2.5-base-v1) offers a small, span-returning **schema-conditioned** English extraction model; it is a later value-arm candidate after S1 has a schema, not a blind schema inducer. [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B) is an Apache-2.0 multimodal challenger already named by the separate schema12 protocol, but its local BF16 fit and corpus accuracy remain unmeasured. Do not add any of these because a vendor benchmark reports a high score on another task.

**Development advance gate (not product release).** S1 must process 60/60 sources to a terminal receipt, recover at least **229/458 raw-exact positive linked cells** and **40/157 strict complete rows** (25.5%) under the frozen-alias alignment, and have at least **95% source-valid locators** in an arm-blind audit of 100 non-null proposals, or all if fewer. Choose the audit deterministically by source SHA-256, then source locator, before inspecting correctness; for receipt images, a valid locator must overlap the visible source text at the claimed word/cell, not merely resolve in an OCR string. On the five synthetic format fixtures, DOCX, XLSX, HTML and PPTX must each reproduce **two linked data rows and six exact data cells**, plus **three separately source-resolvable header cells**; EML must do that or explicitly abstain from its HTML alternative. S1 must make zero automatic releases. These intentionally demanding thresholds test whether a costly next study is justified; they do **not** establish precision or generalization. Report the baseline and S1 paired source differences, including regressions, regardless of gate outcome. A missed threshold stops this candidate profile; do not tune then reuse version 1 scores as a holdout.

**HITL and cost gate.** Model-only scores do not price review. Before a claim of lower total cost, obtain independent, source-only complete gold on a diverse real-document cohort, then have at least two arm-blind reviewers use the same UI for B0 and S1 on counterbalanced source allocations. Capture active inspection/edit time, row and field additions/deletions, evidence checks, overrides, disputes and residual adjudicated errors. Report reviewer variation and per-source time. Measure parser/OCR/model CPU/GPU seconds, energy or priced hardware scenario, memory, storage, retries, provider tokens and settled charges; unknown costs remain `null`. Compare **total cost per correctly released document** only where the fully labelled scope makes that denominator valid. An S1 product candidate needs at least a **20% reduction** in this review-inclusive unit cost versus a fully reviewed comparator while retaining predeclared critical-field correctness, or a demonstrated quality gain within a fixed cost cap. A zero-correct-document comparator has an undefined unit cost; report cost components and quality instead of a fabricated ratio. No reviewer-time or product-cost claim is currently supported.

**Coverage and promotion.** Current English OCR is not validated across languages, scripts, handwriting, poor scans, embedded images, or every native format feature. A real holdout must label format, language/script, born-digital versus scan, long-document status, table structure, and unseen family/template; report coverage and failures separately, with no silent fallback across data-policy boundaries. The current 24,000-character model, 24-field, 50-page PDF and 20 MiB source limits are measured support boundaries, not general-document support. Before promoting any extraction implementation, predeclare slice-specific critical-field precision, strict-row recall, false-release, reviewer-time, p95 latency and cost limits; satisfy them on a source-disjoint fully adjudicated diverse corpus, then run the user's **fresh ≥2,000 distinct original sources end to end through the changed product path**. The earlier no-model 2,000 run remains historical and cannot certify S1. Paper evidence remains unchanged.
